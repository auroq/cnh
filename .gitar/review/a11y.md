# Accessibility review

Wide Door exists for attendees with limited mobility, hearing or vision.
A UI change that makes it harder for them is a bug, not a style note.
For any PR touching HTML, templates, CSS or front-end code, check:

- Every page has one `<h1>`, a descriptive `<title>` and a `lang` attribute.
- Every interactive element is reachable and operable with the keyboard alone, in a sensible order, with a visible focus ring.
- Every image, icon and control has a text alternative; decorative images use `alt=""`.
- Form fields have a visible `<label>` bound by `for`/`id`, and errors are announced, not only coloured.
- Answers and status changes go to an `aria-live` region so a screen reader hears them without moving focus.
- Nothing depends on colour alone; text contrast is at least 4.5:1 and large text 3:1.
- The layout still works at 200% text size and at 320px width without horizontal scrolling.
- No motion that cannot be turned off, no time limits on reading an answer.
- Plain language: short sentences, no jargon an attendee would have to look up.
